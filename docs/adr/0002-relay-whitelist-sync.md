# 中转节点的网络白名单由包装进程轮询服务端并重启 `easytier-core` 来同步

中转节点是一个不带虚拟 IP（不建 TUN）的 `easytier-core`，房间的网络对它来说是"外部网络"。EasyTier v2.6.4 用 `relay_network_whitelist`（空格分隔的通配符列表）决定为哪些外部网络中转：不在名单里的网络连接直接被拒绝；`private_mode` 必须关闭，因为每个房间有各自的网络密钥。这个名单只在启动时读取（`PatchConfig` RPC 改不了 flags，也不监视配置文件），所以名单变化只能靠重启 `easytier-core`。

我们的做法：中转节点容器的入口是一个小的 Go 包装进程 `mokoup2p-relay`。它每隔几秒用共享令牌（`MOKOUP2P_RELAY_TOKEN`）请求服务端的 `GET /internal/v1/relay/networks`，拿到**所有现存房间**（不只是有人在的房间）的网络名；名单变化并稳定 2 秒后，重写配置文件、用 `--check-config` 校验、再重启 `easytier-core` 子进程。启动后、第一次取到名单之前，名单为空（什么都不中转）；之后服务端暂时不可达时沿用上一次的名单。网络名由房间内部标识派生，房主改密码只换网络密钥、不换网络名，所以名单只在创建和删除房间时变化，重启很少发生。

## Considered Options

- **通配前缀（`mokoup2p-*`），从不重启**：最简单，但任何人只要用这个前缀起网络名就能白用中转，违背"只为登记过的房间服务"。
- **服务端把配置写进共享数据卷，由别的东西重启中转容器**：把中转节点绑在服务端所在主机或 Docker 套接字上，权限过大。
- **只登记有成员的房间**：名单随成员进出频繁变化，每次都要重启中转节点。

## Consequences

- 创建或删除房间后几秒内中转节点重启一次：正在经中转的流量会中断几秒后自动重连，成员之间的直连不受影响。
- 服务端多了一个不面向设备的内部接口，用共享令牌鉴权；部署时必须设置 `MOKOUP2P_RELAY_TOKEN`。
- 升级 EasyTier 时要确认 `relay_network_whitelist` 的语义没变（接缝 3 冒烟测试覆盖"未登记的网络无法使用中转节点"）；如果以后的版本支持运行时修改名单，可以去掉重启。
